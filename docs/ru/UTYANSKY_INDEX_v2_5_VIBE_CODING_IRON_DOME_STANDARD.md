## 📌 1. Зачем нужен стандарт v2.5?

При разработке программных систем силами нейросетей (Cursor, Claude Code, Windsurf, Gemini, GPT) разработчики неизбежно сталкиваются с тремя критическими проблемами:
1. **Деградация контекста на больших файлах (> 500 строк):** ИИ теряет фокус, «забывает» объявленные переменные и обрывает зависимости.
2. **Случайные сдвиги верстки и стилей:** Модель, исправляя одну кнопку, параллельно пересчитывает паддинги и смещает соседние блоки.
3. **Искажение системных промптов:** Настройки характера и логики ассистентов перезаписываются «под шумок» при правке обычной бизнес-логики.

**Индекс Утянского v2.5** решает эти проблемы на уровне физической архитектуры проекта.

## 📐 2. Четыре Базисных Правила Разработчика

### 📄 Правило 1. Калибр «4 Листа А4» (Лимит объема файла)
* **Максимальный объем любого файла кода или системного промпта:** **до 4 листов А4 (~350–400 строк / ~3000 токенов)**.
* Если файл растет больше 400 строк, разработчик или ИИ обязаны провести декомпозицию: вынести логически завершенный виджет в отдельный подкомпонент в папку `components/`.

---

### 🛑 Правило 2. Презумпция Заморозки «5 Нулей» (`[IDX: 00000]` / Zero-Trust)
* Все созданные и принятые блоки по умолчанию получают защитный статус:
  ```html
  <!-- [IDX: 71390] [IDX: 00000] -->
  <div data-idx="71390" data-lock="00000" data-desc="Окно демонстрации графиков">
      ...внутренний код блока...
  </div>
  ```
* **Замок ставится только на родительский контейнер** (2–3 пломбы на файл), исключая визуальный шум.
* ИИ запрещено модифицировать блоки со статусом `00000`. Модель работает только с тем слотом, который разработчик прямо указал в запросе.

---

### 🔏 Правило 3. Физическое Капсулирование Ядра (Составной Префикс `00000_{IDX}`)
* Чтобы исключить путаницу между десятками агентов и модулей в сложных проектах, файлы-капсулы именуются по строгому стандарту **`00000_{РОДИТЕЛЬСКИЙ_ИНДЕКС}_{имя_файла}.ext`**:
  * `00000_70000_scout_prompt.json` — Промпт Шпиона для модуля `[IDX: 70000]`
  * `00000_70200_cloe_prompt.json` — Промпт Клоя для модуля `[IDX: 70200]`
  * `00000_70400_oscar_prompt.json` — Промпт Оскара для модуля `[IDX: 70400]`
  * `00000_71390_charts_viewport.jsx` — Окно графиков для модуля `[IDX: 71390]`
  * `00000_30050_order_math.py` — Математика ордеров для модуля `[IDX: 30050]`
* **Эффект:** Префикс `00000` сообщает модели о замке безопасности, а числовой индекс `70200` безошибочно указывает, к какому узлу системы привязана капсула. В файлы интерфейса настройки импортируются в 1 строчку. При верстке UI файлы капсул даже не открываются.

---

### 🪆 Правило 4. Архитектурная Матрёшка для проектов на 5000+ строк
* Крупный проект делится по тысячным долям индекса:
  * `[IDX: 90000] index.py` — Главный диспетчер (до 80 строк).
  * `[IDX: 91000] module_a.py` — Функциональный узел (до 300 строк).
  * `[IDX: 92000] module_b.py` — Функциональный узел (до 300 строк).
  * `[IDX: 91000-00000]` — Закрытые капсулы правил подраздела.

## 🤖 3. Как запустить Скрипт-Страж (Guardian Linter)

Скрипт проверки лежит в папке `examples/guard_utyansky_slots.py`.

### Запуск проверки:
```bash
python examples/guard_utyansky_slots.py
```

### Что проверяет скрипт:
1. 🔢 **Синтаксис [IDX: XXXXX]:** Проверяет, чтобы внутри скобок были строго цифры и тире (ноль букв).
2. 📄 **Лимит 4 Листов А4:** Находит файлы длиннее 450 строк и сигнализирует о необходимости декомпозиции.
3. 🔒 **Поиск коллизий $O(1)$:** Гарантирует уникальность каждого координатного слота.
4. 🛑 **Контроль пломб 00000:** Проверяет наличие защитных замков на контейнерах.
